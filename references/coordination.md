# 项目记录与交接

## 唯一记录

每个制作项目在用户指定的项目目录维护一份 production-state.md；已有等价记录就复用，不另建竞争副本。未确定保存位置时先在对话维护并询问所需位置，不猜测存在的目录。技能目录只保存通用规则，不放用户项目素材。跨项目记忆依照所在环境的用户规则写摘要与原资料指向。

总控是状态写入者。更新前重读，保留他人修改与历史。子 Agent 只反馈结果，不自行更改用户确认状态。

## 最小记录结构

- 项目：当前阶段、需求版本、剧本版本、下一步。
- 决定：内容、来源/日期、确认或建议或假设。
- 交付表：交付物、责任角色、版本/路径、状态、检查证据、待办。
- 资产表：编号、类型、名称、场次、版本、路径、生成/检查/用户确认状态。
- 片段表：段号、剧本版本、资产依赖、提示词版本、上传映射、素材状态。
- 变更：修改内容、影响范围、被替代版本、待修订项。

状态：待开始、制作中、待你确认、已确认、待修订、等待资料/素材。提示词完成、素材生成、素材检查、素材确认分别记录。报告确切数量如3/5角色已确认，不凭空报百分比。写文件不代表检查通过；子 Agent 完工不代表用户确认。

## 派发契约

给每个专业子 Agent：角色和对应说明路径；具体目标及范围；有效需求/剧本/资产版本及可读材料；用户已确认约束；输出形式与检查标准；需要反馈的未决问题。限制默认不生成媒体、不外发、不改共享状态、不再派生Agent。需要落盘时分配明确文件所有权，注明共享工作区、保留其他人修改。所有子 Agent 遵守上级工具权限和用户授权范围。

返回：实际产出或路径、引用版本、完成项、自检与证据、未验证项、问题及建议。总控检查后统一对用户表达；每轮少量问题。

## 调度和修改

四角色按需顺序调度，遵守实际并发上限，不要求同时驻留。委派必须使用真实子Agent工具并确认结果；没有工具则说明限制，请用户选择是否接受四角色代行。

改选题→策划，检查剧本及下游；改故事/台词→编剧，检查资产和分镜；改外观/声音/空间/道具→美术，检查相关镜头；改节奏/动作/镜头→分镜，检查时长连续性。列依赖后只修相关成果，旧版本保留并标被替代，不整套重做。

## 完成边界

用户确认的需求卡、按需剧本、资产清单/设计提示词、声音设定、Seedance分段提示词及项目记录构成首版交付。媒体生成、视觉/听觉检查和最终剪辑分别跟踪。停止或中断时保存当前有效版本、缺项和下一步，未知结果不得填为完成。
